# AI Character Engine 開源教材與實作路線：28–36

更新日期：2026-09-22  
文件狀態：後續開發路線；本文件不表示各冊教材、程式或實機驗收已完成。

本路線要把 AI Character Engine 接入 Tomoshibi，逐步交付能自行部署、持續互動、保留長期記憶、執行多步任務並恢復故障的角色系統。程式、繁體中文教材、測試與可重現範例必須一起推進。

目前從第 28 冊開始。Engine v0.24 是第 28 冊的目標版本，不是已發行版本，也不是 Tomoshibi 應用程式的版本。其餘冊次的 Engine 版本號，在實作範圍與相容性確認後再編定。

執行入口見 [WORKER_HANDOFF.md](WORKER_HANDOFF.md)。一般使用者不需要先讀開發交接文件。

## 1. 交付原則

- 通用引擎與 Tomoshibi adapter 分層；引擎不可依賴特定前端、角色模型或語音供應商。
- 保留完整原始碼、可編輯教材、設定範本、安裝／貢獻／相容性文件。
- 每一階段都有不用付費 API 的離線範例與測試；另列真服務與真人設備驗收。
- 可使用本機模型。假 provider 的測試結果不能當成真模型效果、延遲或硬體驗收。
- 保留既有授權、NOTICE、上游歸屬與素材聲明；不因後端採 MIT 就將前端、模型權重、聲音或角色素材全部重授權。
- 每次發行列出來源 commit、依賴與模型版本、測試證據、限制及回滾方式。
- 對公開讀者提供真正可取得的程式來源。尚未建立的 GitHub 發行或 PyPI 套件，不可寫成可用安裝步驟。

## 2. 執行順序

| 階段 | 冊次 | 結果 |
|---|---|---|
| 接入與可靠性 | 28–30 | 在真實宿主完成互動，能中斷、恢復與管理自主工作 |
| 規劃與持續感知 | 31–33 | 能追蹤多步任務，結合角色狀態與多模態資訊做出行為 |
| 真實訓練、驗收與交付 | 34–36 | 完成模型比較、長時間品質證據及可重現部署 |

依序解決每冊的依賴。評估資料集、授權清冊和測試工具可提前準備；不能因文件先寫完就把依賴中的功能標為完成。

## 3. 第 28 冊：Tomoshibi 原生整合與端到端實戰

**目標：** 讓既有 Engine 進入真正的 Tomoshibi 對話與輸出流程。

內容與交付：

- 梳理宿主、Agent、Runtime、Bridge、provider 的責任與生命週期。
- 新增可選的 Character Engine adapter、型別化設定與完整預設範本。
- 將文字、ASR 轉錄及帶來源的圖片輸入交給對應能力；不支援的媒體必須有明確結果。
- 將已成功交付的角色回覆轉換為既有字幕、TTS、表情與動作輸出。
- 同一角色 session 的一般輸入與主動輸入共享 Runtime、租約與取消規則。
- 處理空輸出、阻擋、失敗與副作用不確定的 held 工作。
- 提供離線整合範例、本機模型操作流程及真設備驗收表。

**完成門檻：** 現有 agent 預設路徑不退化；不安裝可選 Engine 依賴仍能啟動；不同 session 不互相污染；取消及關閉後沒有過期輸出；完整範例可由乾淨環境重現。公開 Engine 原始碼來源是尚待完成的前置條件。

## 4. 第 29 冊：即時互動、插話與中斷控制

**目標：** 使用者插話後，舊回合不再影響新的回合。

- 設計 turn ID／generation、取消傳播和輸出有效性檢查。
- 協調 LLM 串流、文字切句、TTS 合成、播放、字幕及 avatar 動作。
- 處理背壓、有界佇列、佇列順序及過期工作。
- 分別量測首字、首音、插話到停播和完整回覆延遲。
- 分開「取消 Python task」與「已送入服務或執行緒的工作真正停止」。

**完成門檻：** 連續插話、慢 TTS、網路錯誤、已排隊音訊等情境均有證據；舊回合不能在新回合播放。若供應商無法中止合成，記錄其資源限制，同時確保結果不再交付。

## 5. 第 30 冊：可靠自主行為與持久化執行

**目標：** 排程跨重啟保留，故障不造成失聯工作或盲目重做工具。

- 設計持久化候選佇列、claim、lease、ack、release 與 crash recovery。
- 為工具建立穩定 operation ID、冪等記錄及副作用確認流程。
- 提供 held 工作的檢視、恢復、丟棄與原因紀錄。
- 處理重試上限、退避、到期、時區、冷卻與重複事件。
- 定義工作完成、輸出交付、外部副作用三者的持久化邊界。

**完成門檻：** 在各提交邊界強制停止並重啟，能說明每筆工作的去向；不聲稱跨外部服務有無條件 exactly-once 保證。多程序能力若未實作，必須明確限制部署拓撲。

## 6. 第 31 冊：目標、任務拆解與規劃執行

**目標：** 從單輪回覆進入可觀察、可取消、可恢復的多步任務。

- 建立目標、步驟、依賴、輸入與結果的型別化資料。
- 執行前檢查工具權限與任務邊界。
- 保存進度與產物，檢查成功條件，處理失敗重規劃。
- 加入預算、最大步數、停止條件與人工介入。
- 將執行事實和模型提議分開保存。

**完成門檻：** 固定任務集可重現成功／失敗；不把模型自稱完成當成工具執行證據；中斷後續跑不重做已確認的副作用。

## 7. 第 32 冊：主動行為選擇與長期角色發展

**目標：** 讓情緒、關係、記憶與習慣影響行為，且能解釋及評估。

- 將已有角色狀態映射到候選行為及評分。
- 處理動機衝突、抑制、主動頻率與安靜時段。
- 分開短期情緒、持久關係、穩定人設與可變習慣。
- 控制長期漂移，保留使用者可調整和重設的途徑。

**完成門檻：** 同一輸入在不同狀態有可驗證的差異；人設、記憶與關係不互相矛盾；長時間互動不演變成無限制主動輸出。

## 8. 第 33 冊：持續感知與多模態情境理解

**目標：** 聲音、畫面與事件形成帶來源及時效的情境。

- 設計觀察時間、來源、可信度、有效期限及引用關係。
- 處理聲音／畫面不同步、重複觀察、資訊矛盾與過期證據。
- 依成本與情境分配注意力，決定何時感知、何時回應。
- 管理相機、螢幕及錄音的啟用狀態與資料保留範圍。

**完成門檻：** 固定多模態樣本能重播；觀察過期後不得被當成當下事實；沒有影像證據時不能捏造看見的內容；停用感知後不再讀取該來源。

## 9. 第 34 冊：角色模型微調完整實戰

**目標：** 延伸既有 Hugging Face／SFT／LoRA 教材，完成真實訓練與公平比較。

- 整理可公開或合法再散布的資料與資料說明。
- 切分訓練／驗證／測試集，處理洩漏、重複與角色一致性。
- 記錄 GPU、記憶體、基礎模型 revision、設定、seed 和依賴。
- 完成 LoRA／QLoRA 訓練、評估、adapter 載入及回滾。
- 比較原模型、提示調整與微調結果，包含退化案例與成本。

**完成門檻：** 有實際訓練紀錄與未參與訓練的評估結果。沒有 GPU 或模型存取時只能標記「待實跑」，不得以設定檔或假結果替代。權重能否公開依各模型與資料授權判定。

## 10. 第 35 冊：整體品質評估與長時間驗收

**目標：** 評估整個互動系統，而非只有單一模型分數。

- 整合人設、記憶、工具正確性、主動時機、語音延遲與成本。
- 建立版本比較、固定情境、隨機種子及可重播紀錄。
- 執行斷線、逾時、服務失效、磁碟問題與中途重啟測試。
- 檢查長時間運作的記憶體、工作數、佇列與資源清理。
- 對支援的 OS／Python／模型組合建立驗收矩陣。

**完成門檻：** 每個發行阻擋條件都有對應數據、日誌與重現方法；清楚記錄測試時長、機器、模型、門檻及未測項目。不可把一次短測稱作長時間穩定。

## 11. 第 36 冊：正式部署與完整專題交付

**目標：** 新的使用者可以取得原始碼、完成設定、部署並安全升級。

- 提供版本鎖定、設定遷移、安裝與解除安裝。
- 整理單機／伺服器拓撲、權限、金鑰注入及資料保存位置。
- 建立備份、恢復、健康檢查、監控、升級與回滾流程。
- 交付範例角色、模型／素材清冊、第三方聲明與限制。
- 整合前面各冊成為可從零重現的完整專題。

**完成門檻：** 乾淨環境安裝與備份恢復實測通過；發布物可追溯到原始碼與測試；現有使用者有可執行的遷移／回滾步驟。

## 12. 每冊教材的固定結構

1. 學習目標、先備知識與本冊完成後能做的事。
2. 中英術語與核心原理。
3. 資料流、生命週期、責任邊界與架構。
4. 設計選擇、替代方案及取捨。
5. 對應實際版本的完整程式導讀。
6. 可執行範例、設定、輸入與預期結果。
7. 失敗案例、測試及除錯。
8. Tomoshibi／角色系統的應用。
9. 練習、參考解答與驗收。
10. 限制、授權、來源、版本與下一冊銜接。

教材原稿優先保留為可版本控制的文字來源；DOCX／PDF 等閱讀版由原稿產生並做版面驗證。片段須能對應到完整範例，不能只交無法執行的省略碼。
